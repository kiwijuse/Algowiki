## 전체 그림

```
                     ┌───────────────────────────────┐
  Browser ── HTTP ──▶│  Apache + PHP   (웹 · 뷰 계층) │
      ▲              │  index · problem · userinfo   │
      │  AJAX 조각    │  quest · board · category     │
      └──────────────└───────────────┬───────────────┘
                                     │
                             MariaDB (jol)
                                     ▲
                     ┌───────────────┴───────────────┐
                     │  HUSTOJ judged  (C++ 채점기)   │
                     │    └ quest_api ★ 직접 심은 훅  │
                     └───────────────┬───────────────┘
                                     │
                     ┌───────────────┴───────────────┐
                     │  cron 스케줄러 (C++)            │
                     │    daily / weekly quest reset  │
                     └───────────────────────────────┘
```

★ = AlgoWiki가 직접 추가한 부분

**인프라** — AWS EC2(Ubuntu) 단일 인스턴스에 Apache + PHP + MariaDB + HUSTOJ 채점기.

## 퀘스트 진행도는 어디서 갱신되나

이 프로젝트에서 가장 중요한 서버 쪽 결정입니다.

퀘스트 진행도를 올릴 수 있는 자리는 두 곳이었습니다.

| 후보 | 문제 |
|---|---|
| PHP에서 "제출" 눌렀을 때 | 채점 결과가 아직 없음 — 정답인지 모름 |
| PHP에서 "채점 현황" 볼 때 | **안 보면 갱신이 안 됨.** 폴링으로 때우면 중복·누락 |

정답 여부를 **가장 먼저, 정확히 한 번** 아는 주체는 채점기입니다.
그래서 채점기가 결과를 기록하는 그 지점에 훅(`src/judge/quest_api/`)을 넣었습니다.

```
정답(AC) 판정
   │
   ├─ 처음 맞힌 문제인지 확인   (재제출로 보상을 반복 수령하는 것 차단)
   ├─ 문제 정답률 통계 갱신
   └─ 그 사용자의 미완료 퀘스트만 골라 진행도 +1
         일일 / 주간 / 메인 / 히든 분류별로 각각 처리
```

**웹 레이어는 결과를 읽기만 합니다.** 화면에서 진행도를 계산하지 않으니
탭을 열어두든 닫아두든 값이 어긋날 일이 없습니다.

진행도를 올릴 때 **진행률(%)도 함께 저장**해 둡니다.
목록을 그 값으로 정렬하면 **거의 다 깬 퀘스트가 항상 위로** 올라옵니다.

## 매일·매주 초기화

일일/주간 퀘스트 초기화는 cron으로 도는 별도 프로그램(`src/judge/scheduler/`)이 맡습니다.

- 일일 퀘스트 진행도·수령 상태 리셋
- Random-Tag 퀘스트에 **새 태그 무작위 배정**
- 사용자마다 난이도대별로 **아직 안 푼 문제 중 하나를 지목**

마지막 항목이 사용자 수만큼 반복되는 작업이라, 웹 요청 경로에 두면
그날 첫 접속자가 그 비용을 전부 떠안게 됩니다.
그래서 **트래픽이 없는 자정에 한 번만** 도는 프로세스로 분리했습니다.

## 데이터베이스

HUSTOJ 원본 테이블(`users` · `problem` · `solution` 등) 위에
AlgoWiki가 게임화용 테이블을 얹은 구조입니다.

| 테이블 | 화면에서 쓰이는 곳 |
|---|---|
| `uinfo` | 프로필 카드의 EXP · 코인 · 티어 · 칭호, 난이도 표시 설정 |
| `quests` · `progress` | 퀘스트 목록과 진행바 |
| `accept` | "맞은 문제" 표시, 안 푼 문제 골라내기 |
| `pinfo` | 문제 카드의 정답률 |
| `tag` | 태그 필터와 태그/위키 목록 |
| `user_link` | 프로필의 GitHub · Discord · Blog |

`users` 테이블에는 닉네임 색 · 스트릭 색 · 한줄 소개 컬럼을 추가했습니다.

## 이 저장소로 바로 실행되지는 않습니다

**아카이브**입니다. 돌려보려면 [HUSTOJ](https://github.com/zhblue/hustoj) 를 먼저 설치하고,
위 추가 테이블을 만든 뒤 `src/web/` 을 배치해야 합니다.
문제 본문·테스트 데이터·DB 스키마는 서비스 DB에 있었으므로 여기 없습니다.

> 커밋 전 DB 비밀번호는 `CHANGE_ME`, 서버 IP는 `<SERVER_IP>` 로 치환했습니다.
